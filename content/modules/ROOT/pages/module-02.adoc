= Build the Bootable Image

*Lab 2 of 2, Module 2*

[.lead]
**Goal:** Write the production Containerfile, build a bootable container image, then convert it to a VM disk (`disk.qcow2`).

*Time: ~17 minutes (includes an 8–10 minute disk build wait)*

image::bootc-build-pipeline.svg[Four-step pipeline from Containerfile to bootc image to qcow2 disk to VM,width=1000,align=center]

== Write the Production Containerfile

Create the production Containerfile:

[source,bash,role=execute]
----
cat > ~/lamp-bootc/Containerfile.bootc << 'EOF'
FROM registry.redhat.io/rhel10/rhel-bootc:10.1

# Install LAMP stack and firewalld
RUN dnf install -y mariadb-server httpd php php-mysqlnd firewalld && dnf clean all

# Copy application files into the image
COPY app/index.php /var/www/html/index.php
COPY app/myapp.conf /etc/httpd/conf.d/myapp.conf
COPY app/db-setup.sql /var/local/setup.sql

# Copy database initialization service
COPY mariadb-setup.service /etc/systemd/system/mariadb-setup.service

# Enable services to start on boot
RUN systemctl enable mariadb httpd mariadb-setup

# Enable SSH password authentication
RUN sed -i 's/^#PasswordAuthentication yes/PasswordAuthentication yes/' /etc/ssh/sshd_config && \
    sed -i 's/^PasswordAuthentication no/PasswordAuthentication yes/' /etc/ssh/sshd_config

# Configure SELinux to allow Apache database connections
RUN setsebool -P httpd_can_network_connect_db on

# Configure firewall to allow HTTP traffic
RUN firewall-offline-cmd --add-service=http
EOF
----

**Focus on three Image Mode ideas in this file:**

1. **`rhel-bootc` base** — bootable OS image, not only an app runtime
2. **`COPY`** — application is immutable content inside the image
3. **`systemctl enable`** — first boot starts MariaDB, Apache, and DB init

== Build the Bootable Container Image

Build as root so later tooling can use the image:

[source,bash,role=execute]
----
cd ~/lamp-bootc
sudo podman build -f Containerfile.bootc -t lamp-bootc .
----

This takes about 2 minutes.

*You should see a successful tag near the end:*

----
Successfully tagged localhost/lamp-bootc:latest
----

Verify:

[source,bash,role=execute]
----
sudo podman images lamp-bootc
----

*Expected shape:*

----
REPOSITORY            TAG         IMAGE ID      CREATED             SIZE
localhost/lamp-bootc  latest      ...           ...                 ~2 GB
----

The size is large because this is OS + LAMP + app, not a tiny app-only container.

== Configure the Image-Builder User

bootc-image-builder needs a VM login user:

[source,bash,role=execute]
----
cat > ~/lamp-bootc/config.toml << 'EOF'
[[customizations.user]]
name = "core"
password = "redhat"
groups = ["wheel"]
EOF
----

You will SSH as `core` / `redhat` in Module 3.

== Build the Disk Image

Prepare output storage:

[source,bash,role=execute]
----
mkdir -p ~/lamp-bootc/output
----

Convert the bootable container to qcow2:

[source,bash,role=execute]
----
cd ~/lamp-bootc
sudo podman run --rm --privileged \
  -v ~/lamp-bootc/output:/output \
  -v ~/lamp-bootc/config.toml:/config.toml \
  -v /var/lib/containers/storage:/var/lib/containers/storage \
  registry.redhat.io/rhel10/bootc-image-builder:10.1 \
  --type qcow2 \
  --config /config.toml \
  --local \
  localhost/lamp-bootc
----

[NOTE]
====
**Expect 8–10 minutes.** Typical stages:

1. Pull/cache layers
2. Partition the disk
3. Extract container contents
4. Install bootloader
5. Write compressed `qcow2`

In real pipelines this runs in CI once per release, not on every developer save.
====

While it runs, remember the Lab 1 contrast: Lab 1 deployed a mutable app container; Lab 2 is producing a **bootable disk** that carries OS + app together.

== Confirm the Disk Artifact

[source,bash,role=execute]
----
ls -lh ~/lamp-bootc/output/qcow2/disk.qcow2
----

*You should see a large `disk.qcow2` file (about 1 GB+).*

**Checkpoint:** you now have the production artifact. Next module boots it as `lamp-vm` and validates the app.
