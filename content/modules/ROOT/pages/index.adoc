= Lab 2 of 2: Package and Deploy a Bootable LAMP Image

== Welcome to Lab 2!

Welcome back — you're in the right place. This is **Lab 2 of 2** in the Image Mode series for application developers.

In **Lab 1**, you built a real LAMP application (Linux, Apache, MariaDB, PHP) and used **volume mounts** so you could edit files on the host and see changes instantly. That workflow is fast and mutable — perfect for development.

In **Lab 2 (this lab)**, you take that *same* application and change how it is packaged. Instead of mounting files at runtime, you **`COPY`** them into a bootable Image Mode image, turn that image into a VM disk, and prove the stack starts automatically when the VM boots.

.From Lab 1 development to Lab 2 production

**Lab 1 recap (what you already covered):**

* Built a systemd-enabled LAMP development container
* Created the app files (SQL, PHP, Apache config)
* Used volume mounts for instant iteration
* Learned why mounts are great for day-to-day coding

**Lab 2 transition (what you will do now):**

* Treat those app files as production build inputs
* Bake them into an immutable `rhel-bootc` image with `COPY`
* Convert the image to a bootable `qcow2` disk
* Deploy as a VM and validate the app — including the LAMP Application tab in Module 3

*Time: ~35 minutes | Difficulty: Intermediate | Series: Image Mode LAMP (Part 2 of 2)*

== What You Should Focus On

* **Same app, new packaging** — you are changing how the app is shipped, not rewriting it
* **COPY, not mounts** — production files are baked in at build time
* **Boot once, serve traffic** — MariaDB, Apache, PHP, and DB init start automatically
* **Immutable value** — reproducible boots, versionable artifacts, no snowflake VM setup

== Why Image Mode Matters Here

**Image Mode for RHEL** lets you build the operating system as a container image. Most Image Mode labs target platform engineers. This series targets **application developers**:

* You still use Containerfiles and container tooling
* You deliver OS + application as one bootable artifact
* Lab 1 optimized for speed; Lab 2 optimizes for a trusted production boot

== What You'll Build

A bootable disk image that starts a complete LAMP stack:

* RHEL bootc operating system
* MariaDB + Apache + PHP
* Your app files copied into the image
* systemd services enabled for first boot
* Firewall/SELinux configured at build time

No post-boot hand configuration. Boot the VM and validate.

== Lab Flow

**Module 1 — Prepare Production Configuration**  
Review app files and create the first-boot database init service.

**Module 2 — Build the Bootable Image**  
Write the production Containerfile, build `lamp-bootc`, convert to `disk.qcow2`.

**Module 3 — Deploy and Validate**  
Start the VM, prove services and HTTP from the terminal, then enable the Showroom LAMP Application tab.

[NOTE]
====
The **LAMP Application** tab may show "Application is not available" until Module 3. That is normal — Module 1 explains why.
====
