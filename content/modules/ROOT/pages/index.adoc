= Package and Deploy a Bootable LAMP Application

Your LAMP application works great in development with volume mounts. Now transform it for production - files baked into the image, packaged as a bootable VM.

Development and production have different needs. Development needs fast iteration (volume mounts). Production needs immutability (baked-in files). This lab shows the production workflow.

*Time: ~35 minutes | Difficulty: Intermediate*

== What You'll Build

You'll transform the LAMP application into a bootable disk image and deploy it as a VM.

The VM boots with:
- Operating system configured
- Services started automatically (MariaDB, Apache)
- Database initialized
- Application deployed
- Firewall rules applied

No manual setup needed. Just boot and run.

== Why This Lab

Most Image Mode labs focus on platform engineering - building OS images with monitoring tools. This lab focuses on application deployment - packaging a database-backed web application as a bootable image.

You're not managing an OS, you're shipping an application.

== What You'll Learn

- Creating production Containerfiles (COPY vs volume mounts)
- Building bootable images with `rhel-bootc` base
- Creating systemd services for application initialization
- Converting bootable images to VM disks with `bootc-image-builder`
- Deploying and validating immutable applications
- Understanding dev (mutable) vs prod (immutable) workflows

== Prerequisites

- Basic container knowledge
- Familiarity with LAMP stack
- Understanding of systemd services

**Lab 1 recommended but not required:**
- Lab 1 teaches the development workflow
- This lab provides application files for you

== Lab Flow

**Module 1:** Review application files, create database initialization service

**Module 2:** Write production Containerfile, build bootable image, create disk image

**Module 3:** Deploy VM, verify services, test application

== Development vs Production

**Lab 1 - Development workflow:**
- Volume mounts (`-v ~/app:/app`)
- Mutable files (edit anytime)
- Fast iteration (no rebuild)

**Lab 2 - Production workflow:**
- COPY directives (files baked in)
- Immutable deployment (can't edit after build)
- Bootable disk image (complete OS + app)

Same application. Different strategies. Different trade-offs.
