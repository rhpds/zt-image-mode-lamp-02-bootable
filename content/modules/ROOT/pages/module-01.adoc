**Goal:** Confirm the Lab 1 application files are ready, then add the systemd unit that initializes MariaDB automatically on first boot.

== Review the Application Files

These three files are the same application surface from Lab 1. Here they are provided so you can focus on production packaging.

[source,bash,role=execute]
----

----

----

-rw-r--r-- 1 rhel rhel 2.1K ... index.php

Focus on what each file does:

* `db-setup.sql` — schema + seed greetings
* `index.php` — PHP page that reads from MariaDB
* `myapp.conf` — Apache virtual host for the app

Skim the database setup:

[source,bash,role=execute]
----
cat ~/lamp-bootc/app/db-setup.sql
----

Skim the PHP entrypoint:

[source,bash,role=execute]
----
head -20 ~/lamp-bootc/app/index.php
----

The DB connection settings assume MariaDB is local to the future VM — that matches the production image layout.

== Focus: Mounts vs COPY

image::dev-vs-prod-compare.svg[Side-by-side comparison of Lab 1 volume mounts versus Lab 2 COPY-based immutable packaging,width=1000,align=center]

**Lab 1 used volume mounts**

* Files stayed on the host
* Container read them through `-v`
* Great for editing and refreshing quickly

**Lab 2 uses COPY**

* Files are baked into the image at build time
* No host mount dependency at runtime
* Changes require a new image build — that is the production trade-off

Same application. Different delivery contract.

== Create the Database Initialization Service

In Lab 1 you could initialize the database interactively. In production, first boot must do that automatically.

Create a oneshot systemd service:

[source,bash,role=execute]
----
cat > ~/lamp-bootc/mariadb-setup.service << 'EOF'
[Unit]
Description=MariaDB Database Initialization
After=mariadb.service
Requires=mariadb.service

[Service]
Type=oneshot
ExecStart=/bin/bash -c 'for i in {1..30}; do cat /var/local/setup.sql | mariadb -u root && break || sleep 1; done'
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF
----

What to notice:

* `After=` / `Requires=` wait for MariaDB
* Retry loop handles boot timing
* `Type=oneshot` runs setup once
* `WantedBy=multi-user.target` enables it on boot

Verify the file:

[source,bash,role=execute]
----
cat ~/lamp-bootc/mariadb-setup.service
----

== Takeaway Before Module 2

Your production image will:

1. Start from `rhel-bootc` (bootable OS base)
2. Install LAMP packages
3. **COPY** app files and this systemd unit into the image
4. Enable services so first boot is ready to serve

**Value:** one artifact that is immutable, reproducible, and portable across VM targets.
